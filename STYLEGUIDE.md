# Стил-гайд визуального оформления

Как размечать текст уроков. Основа — кастомные типы адмонишенов Material for MkDocs (CSS — `assets/styles/admonitions.css`). Правила плотности взяты из практики техдокументации (Google, Elastic, Microsoft style guides): читатель **пропускает** блоки, когда их много, поэтому редкость выделения = его сила.

## Таксономия блоков

| Блок | Синтаксис (раскрытый) | Синтаксис (свёрнутый) | Состояние по умолчанию | Для чего | Макс/урок |
|---|---|---|---|---|---|
| Аналогия | `!!! analogy "Аналогия: ..."` (янтарный) | `<details class="admonition analogy" markdown="1">` | **свёрнут** | Перенос нового понятия в «мир вокруг нас» — как подброшенная монета, колода карт | 1–2 |
| Интуиция | `!!! intuition "Интуиция: ..."` (фиолетовый) | `<details class="admonition intuition" markdown="1">` | **свёрнут** | Доформальное «почему математика выглядит так» | 1–2 |
| Красный флаг | `!!! red-flag "Красный флаг: «...»"` (красный) | — | раскрыт | Частое заблуждение, «как делать не надо» | ≤ 1 — самый редкий цвет на сайте |
| Совет | `!!! tip "..."` (встроенный) | — | раскрыт | Необязательная оптимизация, лайфхак | ≤ 2 |
| Практика | `!!! practically "Практика: ..."` (зелёный) | `<details class="admonition practically" markdown="1">` | **свёрнут** | «Попробуйте руками» — чисто опциональный эксперимент | 1–2 |
| Примечание | `!!! note "..."` | — | раскрыт | Нейтральный контекст | 2–3 |

**Почему так.** Справочные и «ненавязчивые» блоки (аналогии, интуиции, практика) **свёрнуты по умолчанию**: они расширяют материал, а не предупреждают, и не должны перебивать основной текст. **Красные флаги и советы — раскрыты**: предупреждение не должно требовать клика. Цветовая рамка и иконка остаются видимыми в обоих случаях, поэтому «карта цветов» страницы читается даже без раскрытия.

**Почему свёрнутые кастомные врезки пишутся HTML, а не `???`.** Расширение `pymdownx.details` добавляет к `<details>` только класс типа (`class="analogy"`), но **не** класс `admonition` — а именно на него опираются и стили темы, и наш `assets/styles/admonitions.css`. Поэтому для кастомных типов используем структуру Material целиком: `<details class="admonition analogy" markdown="1">` + `<summary class="admonition-title">Заголовок</summary>`. Для встроенных типов (`note`, `tip`, `warning`…) достаточно обычного `??? тип "Заголовок"`.

## Правила плотности (обязательные)

1. Всего вызовов на страницу — **≤ 5–6**; никогда **не ставим два блока подряд**.
2. Нельзя начинать раздел сразу с блока, класть в блок обязательные шаги (инструкции, зависимости) — они живут в основном тексте.
3. Блок длиннее ~5 строк → либо сжать, либо секция, либо `??? note "..."` (свернуть).
4. Свернутое содержимое (`???`) — для выкладок, зубодробительных деталей, подсказок к «Проверь себя», а также **по умолчанию для аналогий, интуиций и практических блоков**.
5. У каждого блока — **русский заголовок** (без него Material выведет английское имя типа).
6. Аналогия обязана признавать свой предел («аналогия честна до момента …») — это упражнение не для красоты, а против укоренения неверной интуиции.

## Совместимость с просмотром на github.com

Курс читают в трёх местах: на сайте (Material for MkDocs + MathJax), в репозитории на GitHub (движок GitHub) и в редакторе (VS Code и подобные). Сайт переваривает всё, а у GitHub есть свои ограничения — их и описывает этот раздел (правила проверены экспериментально, проба из 20+ вариантов записи).

| Правило | Почему | Как правильно |
|---|---|---|
| В однострочной формуле **нельзя** `\begin{pmatrix}…\end{pmatrix}` | GitHub не понимает блочное окружение внутри `$…$` и оставляет всё текстом | блочные матрицы — только в `$$…$$` отдельной строкой |
| **Матрицы не кладут в таблицы** | в ячейке таблицы нечитаемо, а в GitHub-просмотре не отрисовывается вовсе | таблица — про действие, матрицы — отдельным блоком под ней |
| Подчёркивание сразу после `)` или `}` внутри формулы | Markdown превращает его в курсив: `A_{ik}` → `<em>…</em>`, формула разваливается | переставить множители так, чтобы первое подчёркивание шло после буквы: `$A_{ik} B_{jl} = (A \otimes B)_{ij,kl}$` |
| Цифра сразу после закрывающего `$` | `\$x\$2` не считается формулой | пробел или иная запись |
| `\text{…}` с подстрочными индексами | та же беда с курсивом | `\mathrm{…}` |

Полное оформление курса (формулы, схемы, врезки) — на сайте: <https://dr-dimooon.github.io/qc-design-course/>. В репозитории .md — это исходники, и их вид зависит от просмотрщика.

## Структура заголовков уроков

- `## 📚 Узнать подробнее` → `## ✅ Проверь себя` → `## ➡️ Что дальше` — сквозная последовательность (эмодзи-навигация даёт цветовую ориентацию при скролле).
- Секции внутри урока — обычные `##`, без эмодзи.
- Код-блоки, таблицы и mermaid-схемы остаются «плотным» контентом: не оборачивать их в блоки.

## Терминология

- **Русский текст — по-русски.** Если у термина есть общепринятый русский эквивалент, в
  тексте используется он: «маршрутизация» (не «роутинг»), «маршрутизатор» (не
  «роутер»), «размещение» (не «маппинг» — «маппинг» только в именах пассов и в
  названиях разделов про Sabre), «оптимизация», «транспиляция», «кубит», «гейт».
- **Латинница остаётся в технических именах:** названия пассов и опций API
  (`SabreSwap`, `VF2Layout`, `optimization_level`, `seed_transpiler`), имена методов
  (`transpile`, `count_ops`, `num_nonlocal_gates`), торговые марки (Qiskit, Aer,
  KQCircuits) и устоявшиеся сокращения (CPU, IDE, PDF).
- Первые упоминания латинского термина даём с русским: «маршрутизация (routing)».
  Дальше — только русский.
- Не смешиваем в одном абзаце «роутинг» и «маршрутизация», «маппинг» и «размещение»:
  выбираем одну форму и держим её до конца раздела.
- Названия модулей в тексте — по таблице навигации в [README.md](README.md)
  («00 — Фундамент», «05 — Гардвэйр»); короткие метки в frontmatter (`00 Основы`,
  `05 Железо`) — технические, они совпадают с метками в `curriculum/`.

## Технические заметки

- Тело блока — с отступом 4 пробела; после строки `!!!` или `???` оставляем пустую строку.
- Свёрнутый блок (`???`) рендерится как `<details class="admonition analogy">` — кастомный CSS работает и для раскрытых, и для свёрнутых врезок (селекторы `.admonition.X` и `details.X`).
- Иконки кастомных типов заданы через CSS `mask-image` (`analogy`, `intuition`, `red-flag`, `practically`); обычный `tip`/`note` — иконки темы.
- Расширения `attr_list` + `md_in_html` уже включены в `mkdocs.yml` (нужны для grid/annotate, если понадобятся).
- Вложенные блоки не наследуют цвет родителя — CSS использует только дочерние селекторы; не удаляйте `>` в селекторах.

## Примеры

```markdown
<details class="admonition analogy" markdown="1">
<summary class="admonition-title">Аналогия: монета в воздухе и монета под стаканом</summary>

Подброшенная монета в полёте — суперпозиция…

</details>

!!! red-flag "Красный флаг: «кубит = random() с бонусами»"
    Случайность — лишь один слой…

<details class="admonition note" markdown="1">
<summary class="admonition-title">Доказательство детали (свернуто)</summary>

Выкладка, которую не обязаны видеть все читатели.

</details>
```

> **Атрибут `markdown="1"` обязателен** для любого `<details>`: без него содержимое попадает в HTML как есть и читателю показывается сырой текст (неразобранные `**жирный**` и ссылка в квадратных скобках с адресом в скобках) вместо разметки. Тело внутри `<details>` должно быть **без отступа** (иначе оно станет блоком кода).
