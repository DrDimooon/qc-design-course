# Как предлагать правки в курсе

Курс открыт для правок. Помощь приветствуется — особенно там, где вы столкнулись с непонятным местом.

## С чего начать

1. **Нашли ошибку в факте, формуле, числе или ссылке** → Issues → шаблон «Ошибка в материале». Укажите файл, строку, что не так и как правильно (со ссылкой на первоисточник).
2. **Не поняли, как устроен какой-то кусок** → Issues → шаблон «Вопрос по курсу». Это не «плохой вопрос», а сигнал, что курс надо править: так находятся самые тёмные места.
3. **Есть идея, как сделать лучше** → Issues → шаблон «Идея или улучшение».
4. **Пришлите правку сразу** → Pull request (шаблон просит отметить проверки).

## Правила оформления (важно, чтобы сайт собирался корректно)

- Формулы: однострочные — только простые (`$x$`, `$A_{ik}$`); матрицы и всё с `\begin{...}` — **только блочными** `$$…$$` и **вне пунктов списка** (внутри списка GitHub их не отрисует). Матрицы не кладут в таблицы.
- Врезки-аналогии — свёрнутые (`<details class="admonition analogy" markdown="1">`), красные флаги — раскрытые.
- Ссылки на свои файлы — относительные; ссылки на внешние материалы — с указанием, что проверено.
- Правка одного урока = один PR: так проще обсуждать и откатывать.

## Проверки перед отправкой

```bash
python tools/check_docs.py          # ссылки, блоки кода, frontmatter
python tools/build_site.py --strict # сборка сайта: предупреждения = ошибки
node tools/js/qc-core.test.js      # тесты интерактивного ядра
```

После пуша в `main` GitHub сам прогонит те же проверки (workflow `Course checks`) и пересоберёт сайт (workflow `Deploy course site to GitHub Pages`).
