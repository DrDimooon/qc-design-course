# Capstone-проекты

Capstone-проекты — это финальные практические работы курса: в отличие от лаб (короткие упражнения, встроенные в модули), каждый capstone — самостоятельная задача «от постановки до релиза», требующая комбинирования навыков нескольких модулей. Именно проекты превращают пройденные уроки в портфолио: их результат (ноутбук + код + README решения) можно показывать работодателю как доказательство компетенции.

Три уровня сложности: проекты 02–03 — классические алгоритмы (после модуля 03), проект 01 — core-задача курса (после модуля 04), проекты 04–05 — архитектура и гардвэйр (после модулей 04–05).

| Слой | Что входит | Ориентир |

Рекомендуемый порядок при желании пройти больше: 03 (или 05 для hardware) → 01 → 04 → 05 (от алгоритмов к системному проектированию), либо по интересам трека: software — упор на 01/04, hardware — 05.

## Единая рубрика capstone-проектов (100 баллов)

Рубрика общая для всех проектов; она **совместима** с существующими acceptance criteria и checkpoint-ами внутри каждого проекта — те остаются рабочими шагами, а рубрика задаёт итоговую оценку. Внутри блока «доказательство» оценивается по шкале 0–4 (0 — отсутствует, 1 — частично, 2 — корректно, 3 — инженерно качественно, 4 — exceptional) и нормируется в баллы блока.

| Критерий | Баллы | Что считается доказательством |
|---|---:|---|
| Correctness | 25 | метрики посчитаны верно (например, «2q» — именно двухкубитные операции, а не `num_nonlocal_gates()` без оговорки), результаты проходят собственные тесты/assert-проверки |
| Methodology | 25 | корректный дизайн эксперимента: число seed'ов и обоснование, baseline для сравнения, контрольные условия, осознание ограничений (compile_time, шум, топология) |
| Reproducibility | 20 | lock-файл/версии, фиксированные seed, точные команды запуска, воспроизводимый артефакт (ноутбук/скрипт + таблица или файл ожидаемых результатов) |
| Analysis | 20 | распределения (median/IQR, интервалы), а не одно среднее; объяснение причин, отказ от подгонки, честный вывод «данных недостаточно» |
| Communication | 10 | README решения: постановка, команды воспроизведения, 3–5 ключевых результатов, ограничения; графики с подписями и единицами |

**Порог «сдано»:** ≥ 60/100 и ни один из блоков Correctness/Methodology/Reproducibility не ниже 50 % своего максимума. Оценивать «красоту» ноутбука без воспроизводимости нельзя: Reproducibility — входной билет.

**Checkpoint-совместимость.** В проектах 01 и 04 уже есть поэтапные checkpoints (постановка → прототип → замеры → анализ); они соотносятся с блоками рубрики: прототип — Correctness, замеры — Methodology + Analysis, финальная сдача — Reproducibility + Communication (анализ и объяснение — через Analysis/Communication по итогам всего проекта). Если автор проекта добавил собственные критерии, они уточняют, но не отменяют эти пять блоков.

## Как оформить решение

Стандарт оформления для каждого проекта:

1. **Jupyter-ноутбук** — основное решение: постановка задачи, ячейки с кодом, промежуточные выводы, интерпретация результатов (графики, таблицы метрик).
2. **README решения** (например, `01-transpiler-benchmark/solution.readme.md` или папка решения с README): что сделано, как воспроизвести (точные команды, зависимости с версиями), ключевые результаты в 3–5 пунктах, ограничения и идеи улучшений.
3. **Код** при необходимости выносите в модуль/папку рядом с ноутбуком; избегайте клеевого кода в ноутбуке в пользу импортируемых функций.
4. Указывайте, какие уроки и лабы курса были использованы — это поможет при контрольном прохождении по [PROGRESS.md](../PROGRESS.md).

## Актуальность и применение (2024–2026)

- **Обзор 2025 года классифицирует solver-, heuristic- и ML-подходы к qubit mapping/routing и очерчивает открытые проблемы по трём архитектурам** — [arXiv:2505.16891](https://arxiv.org/abs/2505.16891) — проект [04-qubit-mapper](04-qubit-mapper.md): ваш собственный маппер стоит сверять с этим срезом (какие метрики считать, как бенчмаркить, где остаётся окно для улучшений относительно Sabre), чтобы он был исследованием, а не упражнением.
- **QAOA на LABS в связке с квантовым поиском показал потенциальное ускорение на процессорах Quantinuum (Science Advances, 2024), а аналоговый QAOA запущен на коммерческой нейтрально-атомной QPU Pasqal (2025)** — [arXiv:2308.02342](https://arxiv.org/abs/2308.02342), [arXiv:2501.16229](https://arxiv.org/abs/2501.16229) — решения проектов [02-grover-oracles](02-grover-oracles.md) и [03-vqe-h2](03-vqe-h2.md) теснее к текущей повестке: те же семейства задач (поиск + вариационная оптимизация) — главный полигон проверки квантовых эффектов на железе 2024–2026.
- **IBM Nighthawk (ноябрь 2025): квадратная решётка на 120 кубитов и 218 куплеров вместо heavy-hex Heron** — [IBM Newsroom](https://newsroom.ibm.com/2025-11-12-ibm-delivers-new-quantum-processors,-software,-and-algorithm-breakthroughs-on-path-to-advantage-and-fault-tolerance) — проект [01-transpiler-benchmark](01-transpiler-benchmark.md): сравнение depth/SWAP/2q-gates стоит снимать не только по линейной/тяжёлой топологии, но и по плотным решёткам новейших поколений, где routing почти исчезает и приоритет смещается на выбор layout.
- **KQCircuits активно развивается IQM (релизы 2024–2026, open-source-сообщество, экспорт масок и симуляций)** — [GitHub](https://github.com/iqm-finland/KQCircuits) — проект [05-kqcircuits-chip](05-kqcircuits-chip.md): вы работаете не с архивом, а с живой индустриальной экосистемой; параметризованный «PDK-подход» к дизайну QPU — текущая практика фабричных флоу, что делает capstone реалистичным портфолио-кейсом.

## Связь с ROADMAP

- После каждого из этапов 3–5 из [ROADMAP.md](../ROADMAP.md) логично закрыть первый доступный проект соответствующего блока.
- Веха «первый capstone» в ROADMAP закрыта, когда сдан любой проект с полным оформлением.
- Веха «все 5 capstone-проектов» — long-term goal курса; обязательный маршрут закрывает один capstone (см. выше), остальные — портфолио. Рубрика одного проекта и [final-exam](../tests/final-exam.md) с промежуточной проверкой [Qiskit API readiness](../tests/certification-quiz.md) не «заменяют» друг друга: проект показывает инженерную работу, экзамен — понимание.
