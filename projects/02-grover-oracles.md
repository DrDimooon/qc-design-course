# Capstone: Набор оракулов для алгоритма Гровера (3-SAT)

## Цель

Построить несколько фазовых оракулов для алгоритма Гровера на задачах 3-SAT (CNF-формулы), провести полный цикл: формула → CNF → фазовый оракул → Grover-итерации → счёт успехов на симуляторе; затем сравнить идеальные и шумные прогоны. Главный прикладной вывод: под шумом оптимальное число итераций Гровера смещается вниз.

## Что вы научитесь

- превращать логическую формулу в фазовый оракул (phase oracle): переворот фазы решения $|w\rangle \to -|w\rangle$;
- работать с диагональными унитарными матрицами (`DiagonalGate`) и/или синтезом через MCX-контроль;
- считать оптимальное число итераций $k \approx \lfloor \pi/4 \sqrt{N/M} \rfloor$ и объяснять его вывод через амплитудную геометрию ([урок Гровера](../curriculum/03-algorithms/01-grover.md));
- строить NoiseModel (деполяризация + readout error) и корректно сравнивать ideal vs noise (одинаковые seeds, shots);
- формулировать практичный вывод: под шумом «лишние» итерации Гровера вредны — success-кривая имеет максимум, а не плато.

## Пошаговый план

### Шаг 1. Формулы

Сгенерируйте 3–5 экземпляров 3-SAT (n = 3..6 переменных, m = 2..4n клозов): случайные клозы вида $(l_1 \lor l_2 \lor l_3)$ с литералами из $\{x_i, \neg x_i\}$; фильтр — существует хотя бы одно удовлетворяющее назначение (иначе неинтересный случай M = 0).

### Шаг 2. Оракул из truth table

Оракул должен переворачивать фазу тех базисных состояний, на которых формула истинна. Простейший корректный путь — диагональная унитарность:

```python
from qiskit.circuit.library import DiagonalGate
diag = [-1 if truth_table[i] else 1 for i in range(2 ** n)]
oracle = QuantumCircuit(n)
oracle.append(DiagonalGate(diag), range(n))
```

Для n <= 6 это быстро и без ошибок. Альтернатива «физичнее»: собрать оракул по клозам — для каждого клоза выделить флаг-кубит от неисполненного клоза, применить MCZ от флага, затем uncompute; такой оракул ближе к реальным компиляциям. Допустимый fallback: `PhaseOracleGate` из `qiskit.circuit.library` — дополнительных пакетов не требует (в Qiskit 1.x/2.x он строится штатным синтезом, `tweedledum` больше не нужен):

```python
from qiskit.circuit.library import PhaseOracleGate
oracle = QuantumCircuit(n)
oracle.append(PhaseOracleGate("x0 & x1"), range(n))   # минус на |11⟩
```

### Шаг 3. Diffuser и полный цикл

```python
from qiskit.circuit.library import GroverOperator
grover_op = GroverOperator(oracle, insert_barriers=True)
qc = QuantumCircuit(n, n)
qc.h(range(n))
for _ in range(k):
    qc.compose(grover_op, inplace=True)
qc.measure(range(n), range(n))
```

### Шаг 4. Идеальный прогон

`AerSimulator(method="statevector")`; для каждого k = 0..k_max соберите success probability по 5–10k выстрелам (shots фиксированы). Проверьте, что пик P(k) лежит в окрестности теоретического оптимума $k_{\text{opt}} \approx \frac{\pi}{4}\sqrt{N/M}$, где M — число удовлетворяющих назначений (аудит вручную).

### Шаг 5. Шумные прогоны

```python
from qiskit_aer.noise import NoiseModel
from qiskit_ibm_runtime.fake_provider import FakeSherbrooke

noise_model = NoiseModel.from_backend(FakeSherbrooke())
sim = AerSimulator(noise_model=noise_model, seed_simulator=42)
```

Сравните success probability curves при том же k: где пик, какая высота, что происходит при k > k_opt.

### Шаг 6. Дальше: углубление

Проведите очистку результатов: (a) сохраните матрицу P(k) ideal/noise по каждой формуле; (b) построьте таблицу «формула → N, M, k_opt_theory, k_argmax_ideal, k_argmax_noise, P_peak_noise»; (c) приложите графики.

### Шаг 7. Практичный insight

Сформулируйте выводы: (1) даже на идеальной машине P(k) осциллирует (пик конечной ширины, не плато); (2) под шумом оптимум смещается к меньшим k — объясните, почему накопленные фазовые ошибки разрушают интерференцию; (3) оцените, при каких M/N рамках алгоритм вообще имеет смысл запускать на текущем железе.

Физическая рамка для интерпретации (справка, не обязательный расчёт): каждая итерация Гровера — вращение в 2D-плоскости {решение, остальные} на угол $\theta \approx 2\arcsin\sqrt{M/N}$; успех максимален в точке $k\theta \approx \pi/2$. Шум не меняет $\sqrt{N/M}$-структуру, но подтачивает когерентность: чем глубже схема, тем больше размытие этого угла — отсюда и смещение оптимума вниз.

## Критерии приёмки

- [ ] >= 3 формулы с полным набором P(k) для ideal и noise; M проверен вручную (таблица).
- [ ] Оракул корректен: statevector-проверка — ровно сдвиги фаз на решающих состояниях, никакой лишней модуляции амплитуд.
- [ ] Различие ideal vs noise: рисунок с обеими кривыми.
- [ ] k_opt вычислен и объяснён через амплитудную геометрию.
- [ ] В README решения — вывод «под шумом оптимальное k меньше» + конкретный численный пример.
- [ ] (bonus) Использован второй шумовой бэкенд — разница объяснена (глубина, домирующая физическая 2q-шибка).

## Расширения

1. **Adaptive-подход**: подбирать k интерактивно (не фиксированное) по промежуточным вероятностям; сравните по shot-cost с заранее выбранным k.
2. **Amplitude estimation**: вместо прямого максимума — оценка M через QAE-подобную итерационную процедуру.
3. **Hardness**: проанализируйте зависимость выигрыша от отношения M/N на малых n (3–5): при каких параметрах Гровер уже сейчас бьёт brute-force на симуляторе?
