# Capstone: Реализация роутера кубитов и сравнение с SabreSwap

## Цель

Реализовать с нуля простой роутер: BFS-поиск пути между кубитами + жадная вставка SWAP-гейтов — и сравнить его против `SabreSwap` из Qiskit на 1D- и 2D-графах связности с фиксированными seed. Заодно — на живом примере прочувствовать, что routing-задача сложна и эвристики вроде Sabre не просто так стандарт де-факто.

Формальная постановка, которую вы реализуете: дана схема $U$ (последовательность гейтов над логическими кубитами) и граф связности $G = (Q, E)$; требуется найти последовательность исполнений и SWAP-цепочку, при которой каждая 2q-операция исполняется между физически соседними кубитами, а унитарность результата совпадает с $U$ (вплоть до перестановки кубитов — своё решение должно совпадать точно).

## Что вы научитесь

- представлять исходную схему как последовательность двухкубитных операций над «логическими» кубитами и хранить текущий маппинг logical→физический;
- BFS по coupling map (граф в виде списка соседей) — найти кратчайший путь между двумя физическими кубитами;
- реализовать SWAP-вставку: выбор соседнего обмена «сдвинуть один из операндов» (жадная эвристика);
- корректно измерять результат: глубина, число вставленных SWAP, число 2q-гейтов, время работы;
- провести строгое сравнение с Qiskit: `transpile(..., routing_method="sabre", seed_transpiler=...)` — на тех же схемах и графах.

## Пошаговый план

### Шаг 1. Структура данных

```python
from collections import defaultdict
class Graph:                       # adjacency list
    def __init__(self, edges):
        self.adj = defaultdict(set)
        for a, b in edges:
            self.adj[a].add(b); self.adj[b].add(a)
    def bfs(self, src, dst):       # кратчайший путь (список узлов)
        ...
```

Топологии: линейная (chain 5–10), кольцо, 2D-сетка 3×3, усечённый heavy-hex (подграф FakeSherbrooke).

### Шаг 2. Тестовые схемы

Схемы без привязки к топологии: `QFT(5)`, `QuantumVolume(5, depth=5, seed=42)`, случайные плотные 2q-схемы (`random_circuit(6, depth=10, seed=...)`), Grover-оракул на 6 кубитах.

### Шаг 3. Роутер (слой за слоем)

Алгоритм:
1. Возьмите следующую 2q-операцию `(a, b)`; определите физические позиции `pa, pb`.
2. Если они соседи — исполните операцию и продвиньтесь к следующей.
3. Иначе — BFS-путь `pa -> pb`; двигайте один из операндов вдоль пути вставками SWAP (жадный «ближайший сосед к цели»), не затрагивая уже заблокированные в этом слое кубиты.
4. Каждый SWAP — физически исполняется на ребре (никогда не ставьте SWAP через расстояние > 1).
5. 1q-операции исполняются там, где сейчас живёт соответствующий логический кубит.

Важно: нижняя граница — не всё так просто; целый слой (parallel SWAP) часто дешевле, чем последовательные вставки. Оцените минимальное число SWAP как `const * distance` с ручной проверкой на мелких случаях.

### Шаг 3a. Проверка корректности роутера

Роутированная схема живёт на физических проводах, а исходная — на логических, поэтому
сравнивать операторы «как есть» (`Operator(routed).equiv(Operator(original))`) нельзя:
размеры обычно разные (логических кубитов меньше, чем физических), а если размеры
совпадают, сравнение всё равно ложно — из-за перестановки кубитов. Корректная
проверка — с учётом итоговой перестановки.

Роутер должен возвращать вместе со схемой карту `phys`: `phys[i]` — физический
провод, на котором в конце оказался логический кубит `i`. Тогда проверка такая:

```python
import numpy as np
from qiskit.quantum_info import Operator

def perm_matrix(phys, n):
    """Матрица перестановки «логические кубиты -> физические провода».
    Индексы — как в Qiskit: бит k отвечает за кубит k (q0 — младший)."""
    Q = np.zeros((2 ** n, 2 ** n))
    for src in range(2 ** n):
        bits = [(src >> k) & 1 for k in range(n)]
        dst = 0
        for wire in range(n):
            if bits[phys.index(wire)]:
                dst |= 1 << wire
        Q[dst, src] = 1
    return Q

n = original.num_qubits
Q = perm_matrix(phys, n)
assert np.allclose(Operator(routed).data, Q @ Operator(original).data)
```

То же самое можно проверить на состояниях: подайте в роутерованную схему
`Q @ psi` (тот же логический вход, разложенный по физическим проводам) и сравните
выход с `Q @ (U @ psi)`. Проверка на схеме `h(0); cx(0,1); cx(1,2); cx(0,2)` на
линии 0–1–2 проходит: жадный роутер вставляет 2 SWAP и даёт `phys = [2, 0, 1]`.

### Шаг 6. Выводы

Обсудите: (1) когда ваша жадная эвристика догоняет Sabre (редкий 2q-конфликт, простые графы); (2) почему routing действительно трудна (сведение к token swapping на графах — NP-hard); (3) что терпит главный выигрыш Sabre: co-optimization layout+route, а не только route.

## Критерии приёмки

- [ ] Роутер работает на 4 топологиях и >= 4 схемах и возвращает схему вместе с картой `phys` (логический кубит -> физический провод).
- [ ] Число SWAP, depth и время — таблица сравнения с Sabre на 5 seeds.
- [ ] Проверка корректности: роутерованная схема даёт исходную унитарность с точностью до перестановки кубитов — `Operator(routed).data == Q @ Operator(original).data` (см. Шаг 3a; прямое `Operator(routed).equiv(Operator(original))` здесь всегда `False`, потому что схемы живут на разном числе кубитов).
- [ ] В README решения — выводы с числами, не менее 3 содержательных утверждений.
- [ ] (bonus) Реализация второй эвристики (расстояние до цели + степень свободы узла).

## Расширения

1. **Lookahead**: жадно выбрать SWAP не по BFS-длине, а по сумме оставшихся расстояний для ближайших операций (lookahead-эвристика на 2–3 слоя).
2. **Optimal routing в мини-задаче**: при фиксированном маппинге — exhaustive поиск минимальной SWAP-стратегии на очень маленьких графах (n <= 4); сравните с вашим greedy.
3. **Routing + Layout вместе**: реализуйте простую сабр-подобную эвристику начального layout (по подвыборке случайных аспектов схемы).
