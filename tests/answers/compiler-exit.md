# Ключ и рубрика: Compiler Exit

Сначала выполните [90-минутное задание](../compiler-exit-exam.md). Здесь приведены ожидаемые инварианты и критерии оценивания, а не таблица «правильных» depth или готовый benchmark-скрипт. Оценка не зависит от победы level 3, ring или наличия разброса.

## A. Понятия и чтение кода — 20

В каждой строке **0** — нет ответа либо основная идея неверна; **2** — верное ядро, но пропущены указанные связи; **5** — раскрыты все ориентиры строки.

| Элемент | Ориентир на 5 баллов |
|---|---|
| A1, 5 | `AnalysisPass` не переписывает DAG, записывает `two_qubit_count` в `property_set`. Порядок: init → layout → routing → translation → optimization → scheduling. Для итогового нативного счёта нужен срез после translation/optimization; для routing-overhead — явно определённая граница routing. Обосновано, почему эти числа различаются. |
| A2, 5 | Физические провода могут быть переставлены. Прямое сравнение операторов без layout может дать False при корректной компиляции; равенство тоже возможно при тождественной конечной карте. Нужны обе карты либо layout-aware API. Вход без финального разворота не равен канонической QFT в той же нумерации выходов. |
| A3, 5 | Считаются только финальные явные SWAP. Нативный базис задания не содержит SWAP, поэтому ноль не означает отсутствие маршрутизации. Для вставок нужен инструментированный routing-only срез/отдельный router и разделение исходных и вставленных SWAP; Δ2q после полного pipeline не равен числу SWAP. |
| A4, 5 | Сумма duration — work, depth — структурные слои, makespan — критический путь с длительностями и расписанием, compile time — классическая стоимость. Более дорогой поиск не гарантирует лучший objective. В SABRE backward-проход уточняет layout между попытками, а SWAP-score использует front/extended set и, в decay-эвристике, штраф за недавнее использование. |

## B. Корректность — 30

Для каждой строки **0** — проверка отсутствует/неверна; **5** — указанный частичный результат; **10** — полный инвариант на всех 20 выходах и письменное объяснение. Одна демонстрация на удобном seed не заменяет проверку всей сетки.

| Элемент | Частично, 5 | Полностью, 10 |
|---|---|---|
| B1 — Target | Проверен базис либо рёбра, но не полная инструкция | Ширина 4; для каждой инструкции проверены имя, упорядоченные индексы qargs и поддержка параметров соответствующим Target, например `instruction_supported(operation_name=..., qargs=..., parameters=...)`; нарушение останавливает запуск |
| B2 — семантика | Проверка на одном входном состоянии, части сетки либо без корректного layout | Полный оператор каждого результата эквивалентен `Operator(qc)` с точностью до общей фазы; layout-aware `Operator.from_circuit` или эквивалентная явная перестановка; `assert`/исключение при расхождении |
| B3 — layout | Карта только напечатана либо объяснена без связи с проверкой | Для каждого выхода сохранена конечная logical→physical карта, проверено, что это перестановка 0…3. Указано тождественное начальное размещение. Семантическая проверка действительно учитывает layout; объяснено, почему совпадение счётчиков или вероятностей на одном состоянии недостаточно |

При явной формуле для тождественного начального размещения и одинаковой ширины: `U_routed ≈ P_final @ U_input`, где `P_final` переносит бит логического q на `phys[q]`. При произвольном начальном размещении нужна также входная перестановка. Нельзя подавать `P_final @ psi` как начальное состояние, если фактический начальный layout тождественный. `Operator.from_circuit` снимает необходимость вручную строить обе перестановки для схемы с корректной метаинформацией layout.

Фиксированная QFT имеет четыре кубита, не содержит измерений и финальных разворачивающих SWAP. Оба Target имеют четыре кубита, `rz/sx/x/cx`, по две ориентации каждого ребра. Не требуйте конкретных depth, CX-count, конечной перестановки или различий seeds. В нативном результате ожидается отсутствие явного SWAP, но это не измерение вставок роутера.

## C. Метод — 30

В каждой строке **0** — отсутствует/ошибочно; **2** — правильное направление с существенным пробелом; **5** — выполнен весь ориентир.

| Элемент | Ориентир на 5 баллов |
|---|---|
| C1 — сетка, 5 | В CSV ровно 20 уникальных `(target, level, seed)`: оба Target, уровни 0/3, seeds 11/22/33/44/55. Прогревы не попали в выборку; сетка проверяется программно. |
| C2 — метрики, 5 | depth, ровно-2q, финальные SWAP и секунды compile time определены корректно; layout сериализован однозначно; финальный SWAP не назван числом вставок. |
| C3 — timing, 5 | `perf_counter` только вокруг `pm.run`, четыре отдельных прогрева, seeds снаружи и конфигурации внутри, одинаковые условия; накладные расходы и ограничение коротких замеров названы. |
| C4 — агрегаты, 5 | Четыре строки summary; median/Q1/Q3/min/max для depth, 2q и времени получены из raw; правило квартилей указано. Нулевой IQR принимается. |
| C5 — воспроизводимость, 5 | Сохранён исполняемый скрипт и точная команда, версии, CPU, ограничения потоков до импорта и параметры pass manager; другой человек может повторить эксперимент. |
| C6 — границы метода, 5 | Одинаковые seeds трактуются как paired условия, не как одинаковые внутренние траектории. Пять seeds на одной QFT не объявлены доказательством значимости или универсального превосходства. |

## D. Интерпретация и перенос — 20

Для каждого пункта **0** — отсутствует/противоречит данным; **2** — верная идея без нужного обоснования; **5** — полный ответ.

| Элемент | Ориентир на 5 баллов |
|---|---|
| D1 — выбор, 5 | Назван objective, выбор подкреплён своими median/IQR и сравнением времени. При равенстве чисел вывод «ничья по этой метрике» получает полный балл. |
| D2 — trade-off, 5 | Разделены depth, нативный 2q-count и compile time; объяснено, почему они могут ранжировать конфигурации по-разному и почему число уровня/рёбер не гарантирует победу эвристики. |
| D3 — transfer, 5 | Увеличение ошибки 0–3 меняет calibration-weighted proxy: например, сумму ошибок фактически использованных CX или произведение `(1-error)`. Существующие выходы можно пересчитать без новой компиляции; изменение выбранного layout/pipeline требует нового прогона. Не обещан автоматический обход ребра SABRE, чей базовый routing-score топологический. Proxy не назван измеренной fidelity; корреляции/прочие ошибки не учтены. |
| D4 — ограничение, 5 | Конкретное ограничение связано с небольшим проверяющим опытом: например, одна QFT → ещё одна малая схема с другой структурой; короткий timing → повторные чередующиеся замеры. Отделены синтетические свойства Target от данных устройства. |

## Итог

**20 + 30 + 30 + 20 = 100. Сдано: сумма ≥60, B ≥15/30 и C ≥15/30.** Ни сильная теория, ни удачный график не компенсируют отсутствие корректности или метода. Повторный запуск с исправленными проверками допустим как повторная попытка; сохраните, что именно было исправлено в README своего решения.
