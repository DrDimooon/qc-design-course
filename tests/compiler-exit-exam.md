# Compiler Exit: Core + Compiler за 90 минут

Это обязательная компактная проверка после [модуля 04](../curriculum/04-systems-design/README.md), перед **одним** capstone: [01](../projects/01-transpiler-benchmark.md) или [04](../projects/04-qubit-mapper.md). Время входит в существующие ~36 ч модуля 04, заменяя часть резерва повторения. Проверка показывает чтение кода, корректность небольшого эксперимента и инженерную аргументацию; capstone отдельно проверяет самостоятельную длительную работу.

Предпосылки: 00–02, выбранный Core-минимум 03 (**Grover и QFT**) и software/compiler-маршрут 04. QAOA, QEC, модуль hardware, публикации и доступ к QPU не нужны. Все задания выполняются локально на course-stable Qiskit 2.6.0 / Python 3.11. [Полный итоговый экзамен 00–06](final-exam.md) остаётся дополнительным после соответствующих элективов.

Используйте документацию API и свои конспекты; [ключ и подробную рубрику](answers/compiler-exit.md) открывайте после попытки. Подготовка окружения — до начала 90 минут.

## Входные данные

Скопируйте этот **готовый вход**, затем напишите собственный эксперимент. Это не решение заданий B–D и не автоматически запускаемый пример с проверками.

```python
from qiskit.circuit import Parameter
from qiskit.circuit.library import RZGate, SXGate, XGate, CXGate
from qiskit.synthesis.qft import synth_qft_full
from qiskit.transpiler import Target, InstructionProperties

SEEDS = (11, 22, 33, 44, 55)
LEVELS = (0, 3)
qc = synth_qft_full(4, do_swaps=False)  # без измерений и финального разворота

def make_target(undirected_edges):
    target = Target(num_qubits=4)
    for gate, duration, error in (
        (RZGate(Parameter("theta")), 0.0, 0.0),
        (SXGate(), 20e-9, 1e-4),
        (XGate(), 40e-9, 1e-4),
    ):
        target.add_instruction(gate, {
            (q,): InstructionProperties(duration=duration, error=error)
            for q in range(4)
        })
    directed = sorted({pair for a, b in undirected_edges
                       for pair in ((a, b), (b, a))})
    target.add_instruction(CXGate(), {
        pair: InstructionProperties(duration=300e-9, error=0.01)
        for pair in directed
    })
    return target

targets = {
    "line": make_target([(0, 1), (1, 2), (2, 3)]),
    "ring": make_target([(0, 1), (1, 2), (2, 3), (3, 0)]),
}
```

Оба `Target` синтетические, одинаковой ширины, с одним базисом и одинаковыми свойствами общих рёбер. Их параметры — условия задачи, не калибровки физического устройства.

## A. Чтение кода и понятия — 20 баллов, ~20 минут

Прочитайте фрагменты; дайте четыре коротких письменных ответа, а не только названия классов.

```python
from qiskit.transpiler.basepasses import AnalysisPass

class TwoQubitProfile(AnalysisPass):
    def run(self, dag):
        self.property_set["two_qubit_count"] = sum(
            len(node.qargs) == 2 for node in dag.op_nodes())

# Предложенные коллегой строки анализа результата out:
same = Operator(out).equiv(Operator(qc))
inserted_swaps = out.count_ops().get("swap", 0)
physical_time = sum(target[inst.operation.name][
    tuple(out.find_bit(q).index for q in inst.qubits)].duration
    for inst in out.data)
```

1. Аналитический или трансформационный это пасс? Что изменится в DAG и `property_set`? В какой из шести стадий конвейера разумно снимать эту статистику и почему результат зависит от места измерения?
2. Почему строка `same` не является общей проверкой семантики после layout/routing? Объясните роль начального и конечного размещений, а также отличие QFT без финального разворота от канонической QFT.
3. Почему `inserted_swaps` нельзя выдавать за число вставок роутера? Что именно он считает и как получить routing-only измерение?
4. Почему `physical_time` — не makespan? Разделите работу, структурную глубину, длительность по расписанию и время компиляции. Объясните, почему более дорогой поиск level 3 не гарантирует лучшего результата и чем уточнение layout в SABRE отличается от выбора отдельного SWAP.

## B. Корректность эксперимента — 30 баллов, ~35 минут

Напишите скрипт для **2 Target × 2 уровня × 5 paired seeds = 20 записанных прогонов**. Используйте `generate_preset_pass_manager(optimization_level=level, target=target, seed_transpiler=seed)` с `initial_layout=[0, 1, 2, 3]`. Другие настройки оставьте одинаковыми и запишите их. Фиксированное начальное размещение не отменяет необходимости учитывать конечную перестановку.

Для **каждого** результата:

1. Проверьте ширину и поддержку каждой инструкции по её **имени и фактическим qargs** в соответствующем `Target` (для параметризованного RZ проверьте и допустимость параметров через API Target).
2. Проверьте эквивалентность исходной схеме с учётом layout, например через `Operator.from_circuit(out).equiv(Operator(qc))`. Глобальная фаза допустима. На четырёх кубитах проверка полного оператора достаточно мала. Сравнивайте с данным входом, а не с QFT, в которой внезапно появились финальные SWAP.
3. Сохраните конечную карту logical→physical и продемонстрируйте проверку семантики, которая её действительно учитывает. Объясните, почему совпадения counts или числа 2q-гейтов недостаточно.

Проверки должны завершать запуск ошибкой при нарушении инварианта, а не только печатать `False`.

## C. Метрики и метод — 30 баллов, ~20 минут

Сохраните `raw.csv`: `target, level, seed, depth, two_qubit_count, swap_final, compile_s, final_layout`. `two_qubit_count` считает инструкции ровно с двумя кубитами. `swap_final` — только итоговые явные SWAP, включая допустимый ноль после перевода в базис.

- Измеряйте `perf_counter()` вокруг **`pm.run(qc)`**, исключив создание входа и pass manager. Перед записанными прогонами прогрейте каждую из четырёх конфигураций отдельным запуском вне `raw.csv`; всего 20 записанных + 4 прогревочных запуска. Обходите seeds снаружи и конфигурации внутри, чтобы уровни не выполнялись двумя длинными раздельными блоками.
- Зафиксируйте версию Python/Qiskit, CPU, ограничения потоков до импорта Qiskit и область измерения времени. Короткий замер шумный: выводы о latency здесь предварительные.
- Сделайте `summary.csv`: четыре строки по `(target, level)` с median, Q1, Q3 и min/max для depth, 2q-count и compile time. Укажите способ вычисления квартилей, например `numpy.percentile(values, [25, 50, 75], method="linear")`.
- Проверьте, что все 20 ключей уникальны, сетка полная, а наборы seeds совпадают. Пять seeds описывают эту выборку, не доказывают статистическую значимость или устойчивость для всех схем.

## D. Интерпретация и перенос — 20 баллов, ~15 минут

В 250–400 словах:

1. Выберите конфигурацию для этого входа при явно названной цели: например, минимизировать 2q-count, используя compile time как дополнительный критерий. Сошлитесь на свои median/IQR и опишите ничьи.
2. Объясните возможный конфликт depth, 2q-count и compile time. Ни level 3, ни ring не обязаны строго выигрывать. Нулевой разброс и отсутствие улучшения — допустимые результаты.
3. Transfer: связность ring не изменилась, но ошибка **обеих ориентаций** ребра 0–3 стала 0.08 вместо 0.01. Какие данные и score надо пересчитать? Что можно сказать без нового запуска, а что надо проверить? Не требуется получать выигрыш или писать новый routing-алгоритм. Калибровочный proxy не называйте измеренной fidelity.
4. Назовите ограничение эксперимента и предложите один небольшой следующий опыт, который его проверит.
